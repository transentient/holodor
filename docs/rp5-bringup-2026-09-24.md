## 2. What was changed and why (commits on `wp8-rp5-bringup`)

Upstream pocknix-os `main` was fetched by URL into the shared object store
(`git fetch https://github.com/shuuri-labs/pocknix-os.git main`; no remote added, the
classifier refuses remote edits for the agent). Cherry-picks with `-x`; every conflict
resolution is spelled out in the commit message's "Holodor adaptation" paragraph.

1. `bf136be` **sm8250: add gpt to the kernel cmdline** (upstream `8755514`, inherited).
   Conflict: upstream had already moved to `packages/soc/…`; the grub.cfg + PKGBUILD hunks
   were applied by hand to `packages/pocknix-bootloader-sm8250/` (pkgrel 6). profile.conf
   applied clean. `build-packages.sh`'s grub.cfg-vs-profile drift guard passes.
2. `6e29777` **proton: add DXVK-2 cachy variants for sm8250** (upstream `a8b8635`,
   inherited). Adds `packages/proton-cachyos-dxvk2` (CachyOS 11.0-20260703 with the
   20260602 release's DXVK 2.7 dir swapped in; `provides/conflicts/replaces proton-cachyos`),
   `POCKNIX_GPU_DXVK3=no` in `boards/rp5.conf` + `rpflip2.conf`, metapackage dep.
   Dropped: README hunk, `proton-ge-dxvk2` (Holodor has no proton-ge), the sm8550
   metapackage hunk, the pocknix-core.list move (our list keeps `proton-cachyos`; on
   sm8250 the name resolves through `-dxvk2`'s provides because the SOCS gate keeps the
   plain package out of that repo). Our `pocknix-proton-prep` never offers Proton
   Experimental, so upstream's "hide Experimental on DXVK3=no" hunk has nothing to gate.
3. `15ccf1a` **steam: swap dxvk-2.7 donor into Valve ARM Protons** (upstream `d3b4743`,
   inherited + ported). `packages/pocknix-dxvk2-donor` (Valve Proton 11's own DXVK
   2.7.1-467 dlls, 89.7 MB from pocknix.shuuri.net, sha512-pinned). Holodor's
   `pocknix-proton-prep` never took upstream's `apply_proton()` refactor, so the swap was
   ported by hand into our `apply()` for `steamapps/common/Proton 11.0 (ARM64)`: on
   `POCKNIX_GPU_DXVK3=no` boards, if the donor's first dll differs from the tool's, copy
   the donor dir to `dxvk.pocknix-tmp` and `mv` it over `files/lib/wine/dxvk` (atomic;
   write-free on later ticks). **Seedless adaptation: none needed** — the swap keys on the
   downloaded Proton dir, which appears whenever Steam fetches it on the device, and
   `apply()` runs at every session start plus every 20 s from
   `pocknix-proton-prep.service --watch`; there is no bake-time step to adapt. Steam's own
   Proton updates restore DXVK 3; the next tick swaps the donor back. pkgrels: steam 43,
   bsp-sm8250 11, device-sm8250 3.
4. `3c2ba64` **input: sm8250 desktop-mode gamepad calibration** (upstream `fb6c759`,
   inherited; GPcal port, MIT). `packages/pocknix-gamepad-calibration` + `python-pyxel`
   (upstream aarch64 wheel; its `sdl2` dep resolves to Holo's `sdl2-compat`). Metapackage
   pkgrel 4. Dropped: the `pocknix-turnip-*` deps upstream's metapackage carried then.
5. `bbca233` **harness: SOCS gate, swh-plugins, sm8250 firmware reconcile** (invented):
   - `scripts/build-packages.sh`: a package dir with a `SOCS` file (space-separated SoC
     names) builds only for those SoCs — upstream `73e0566`'s per-package `socs` idea
     without the shared/soc directory split. `proton-cachyos/SOCS` = `sm8550 sm8750`;
     `proton-cachyos-dxvk2`, `pocknix-dxvk2-donor`, `pocknix-gamepad-calibration`,
     `python-pyxel`, `swh-plugins` = `sm8250`. No file = every SoC. **sm8750 impact:**
     none in the image; `proton-cachyos` gets one mtime-triggered rebuild of the same
     pkgrel on the next sm8750 `make packages` (publish-repo skips existing assets).
   - `packages/swh-plugins/PKGBUILD`: ALARM `swh-plugins-0.4.17-7` repackaged
     (deps fftw/gsm/glibc present in Holo; ALARM's virtual `ladspa-host` spelled as
     `ladspa`; sha256 from the ALARM db).
   - `scripts/build-image.sh`, sm8250 branch of `install_firmware`: reconcile against
     `kernel/sm8250/config/kernel-firmware.dat` like the sm8750 branch, but comment- and
     glob-aware (`ath11k/QCA6390/hw2.0/*.bin`, `…/RB5/slpi*` checked against the `.zst`
     names Holo ships, never fetched) and warn-only (nothing boot-critical is fetched;
     expected outcome: only `rtl_nic/rtl8153a-4.fw` fetched from upstream linux-firmware).
   - `.gitattributes`: this doc is export-ignored.

Not changed on purpose: kernel stays 7.1.2 (36 patches, the upstream 7.2 resync
`82fbb2e` and the Visionox work skipped); inputplumber target stays `deck`; the
`ROOT_LABEL=POCKNIX_ROOT` / hostname `pocknix` sm8250 profile values stay as inherited.

## 6. Unverified / open

- **Everything on hardware.** This family has never run under Holo Core; the July
  validation was ALARM userland.
- **Panel revision** (Visionox vs CH13726A) — see §1. If the boot art never appears but
  the device is reachable over Wi-Fi/ssh, this is the first suspect (`dmesg | grep -i
  panel`).
- plymouth orientation on a `rotation = <270>` panel with 1920x1080 frames.
- inputplumber `deck` (usbip) target: the sm8750 family moved to `deck-uhid` for suspend
  survival; the RP5 yaml still uses the older target. Suspend-with-controller behaviour
  will differ from the Odin 3. Switching it is a one-line yaml change + capability map

- `pocknix-slot-successful` on the RP5's separate boot LUN (/dev/sde): it only writes
  when the active slot lacks the successful bit; Android's init does the same. Watch
  the journal line on first boot.
- swh-plugins: NEEDED sonames of the ALARM build not ldd-verified in the Holo rootfs
  (fftw/gsm present by name). If the speaker filter-chain fails to load,
  `journalctl --user -u pipewire` will say so; audio still routes (the filter is a
  WirePlumber smart filter in front of the speaker sink).
- DXVK-2 donor swap only exercised by reading; needs a Windows title on the device.
- `[pocknix]` OTA tag `sm8250` does not exist until the first `make publish DEVICE=sm8250`.
- Flip 2 entirely unverified (as before).

## 7. First-boot checklist for Cliff (you drive; I only read state on request)

Card: flash `build/image/sm8250/pocknix-sm8250-sd.img` (§4 has the sha256) with
Rufus/dd — note the Rufus `.img.gz` progress quirk does not apply to a raw `.img`.
This is a **dev** image (not RELEASE): root password `pocknix`, deck password
`pocknix`, sshd enabled with `PermitRootLogin yes`, no Wi-Fi preseeded.

Before the first boot (optional, recommended): put `wifi.txt` on the FAT partition
(label `ROCKNIX`, the one with `EFI/` and `boot/grub/`):

```
ssid=YourNetwork
password=YourPassword
country=JP
```

It is imported by `pocknix-wifi-import.service` before the session starts and renamed
`wifi.txt.imported`; errors land in `wifi-import-error.txt` on the same partition.

1. Insert the card, power on. The RP5's stock boot chain should pick the SD's
   `EFI/BOOT/bootaa64.efi` on its own (upstream and ROCKNIX both boot this way with no
   ABL flash). If it boots Android instead, look for the boot-device selection the
   stock loader offers at power-on — I am not certain of the exact key (the recon says
   Vol+ at boot brings a menu; verify rather than trust it).
2. What to look at, in order: (a) the Holodor boot art (plymouth, ~3-6 s in) — proves
   the kernel, the panel driver and the DRM orientation; (b) a short black gap; (c) the
   Steam bootstrap status screen on tty1 (seedless: "waiting for network" / download
   progress) — proves the session supervisor, autologin and the network stack; (d) Steam
   OOBE in gamescope, landscape, touch and gamepad working.
3. If (a) never comes: give it 3 minutes (first boot grows the root partition), then
   check whether the device joined Wi-Fi (router DHCP list) and ssh in — panel revision
   is the first suspect (§6).
4. If you want ssh on the card: it is already on. `ssh root@<ip>` password `pocknix`
   (dev image). On a RELEASE-style image the recipe is HANDOFF "Release image root
   access" (`passwd`, `systemctl enable --now sshd` as deck, root via
   `systemd-run --wait --pipe -t /bin/bash`).
5. Things I would like from the first session, when you feel like it:
   `cat /proc/device-tree/model`, `dmesg | grep -iE "panel|ch13726|visionox|retroid|ath11k|adsp|q6"`,
   `journalctl -b -u pocknix-sm8250-audio-heal -u pocknix-sm8250-board-select -u pocknix-slot-successful -u pocknix-wifi-import --no-pager`,
   `systemctl --user -M deck@ status pipewire wireplumber`, `aplay -l`,
   `cat /sys/class/power_supply/*/status`, and the panel check `cat /sys/class/drm/card*-DSI-1/modes`.
6. Do not sleep the device with a USB-C hub attached (the Odin rule; unverified here,
   apply it anyway). s2idle is the only sleep mode on this SoC and is expected to work.
7. Nothing on this card touches internal storage or the bootloader. Pull the card to
   get Android back.

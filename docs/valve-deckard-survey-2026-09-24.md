**Important:** the hotfix repo also re-ships *old base* packages (321 names overlap main): `systemd 257.7-2.2` (main 259.3), `gcc-libs 15.1.1+r500-1.2` (main 15.2.1+r604), `llvm/clang 19.1.7`, `rust 1.78.0`, `bash 5.3.3-3`, `chromium 129`, `qt6-base 6.8.0`, `filesystem 2021.12.07-1.26 "Base SteamOS Linux files"`, but *newer* `libdrm 2.4.134` and `pipewire 1.6.8` than main. So the shipped Frame OS is **not** `main` + hotfixes; it is an older/private base (the `*.pvt` mashes, inference) + hotfixes. Pacman picks the *first* repo that has a name, so listing `[deckard-arch-hotfixes]` above `[core]` on a `main`-based system would downgrade systemd/gcc-libs.

[core]

[extra]

## 6. Licensing / redistribution
- Preview repo `readme.md` (verified): "read-only repository provided for browsing and reference", packages from Arch state `97c0a0b4` "with … newer upstream patches containing licensing information required for proper package redistribution" (Arch RFC 40), "provided on an 'as is' basis … solely as a technology preview … not intended for use as a permanent operating system". No redistribution prohibition; no LICENSE/EULA file in the repo or on the mirrors. Collabora's announcement page has no licence language at all.
- Deckard mirrors: no README/LICENSE/EULA anywhere; no signatures. `main` = Arch packages (redistributable per each package's licence, which is exactly what RFC-40 patches were for). Hotfixes carry **proprietary/Valve-terms** content: `deckard-steam-rel`, `deckard-steamvr-rel` (LicenseRef-steam-subscriber-agreement), `deckard-hw-support`, `deckard-kitchen-sink` (Proprietary), `deckard-vulkan-layers-*` (Proprietary MIT), `qualcomm-linux-graphics-driver-kgsl` (Qualcomm blobs), `deckard-uboot` `bootfw.tar.xz` (Qualcomm boot firmware), `linux-firmware-deckard` (custom), `deckard-audio-config` LV2 binaries, `deckard-display-tools`, `deckard-fpga`, `deckard-ftm`. Open ones: kernels (GPL-2.0-only, binary-only so far), gamescope/steamos-manager/mangohud/portals (MIT), steamos-customizations (LGPL), u-boot images (GPL-2.0+ but bundled with blobs), scx-scheds (GPL). Nothing on deckard adds *new* terms to Holo Core itself; the preview's "as is / technology preview" wording is the only text, and it is silent on redistribution.

## 7. Assessment: switching HOLO_MIRROR off the dead preview
- **Mechanically compatible (verified):** deckard `main/` (and each `mash-*`) is the same "mash" product as the preview: same `pacman.conf` shape, `$repo/os/$arch`, `.db.tar.xz`, `system.rootfs.zst` bootstrap tarball, unsigned, plain Arch package names. `HOLO_MIRROR=https://holo-packages.steamos.cloud/archlinux-deckard/archlinux/mash-20260305` (pinned; identical to `main` today) is a drop-in for `scripts/bootstrap.sh`/`build-packages.sh` after updating `HOLO_ROOTFS_SHA256`. Pacman 7.0→7.1 is db-format compatible. The mash cadence is ~quarterly (20251118 → 20260202 → 20260305) plus `main` moving every few days — pin a mash, never `main`.
- **What breaks (verified deltas, consequences are inference):** it is a full toolchain/ABI era change — glibc 2.42→2.43, gcc r301→r604, **python 3.13→3.14** (decky/py_modules, `pocknix-decky`, any `python-*` we install), llvm 21.1.5→21.1.8, libdrm 2.4.129→2.4.131, sdl3 3.2→3.4, vulkan loader/headers 1.4.328→1.4.341, wayland stack newer (check `wayland-protocols-next` pin comment about wayland-scanner 1.24), systemd 258→259, mesa Arch 25.2.7→26.0.1 (irrelevant, we replace it), kernel-headers 6.19. Every `packages/*/PKGBUILD` must be respun against the new chroot; `config/packages/base.list` must be re-resolved (256 preview names are gone — mostly GNOME/haskell/python-* noise, but check gcc14/llvm18 users). The `plymouth`/`scx-seds` "pkgrel > base" trick still works.
- **The hotfixes layer is not a base you can switch to.** It contains an older base than `main` (systemd 257.7, gcc-libs 15.1.1, llvm 19, rust 1.78) so `[deckard-arch-hotfixes]` above `[core]` would downgrade the system, and its Valve packages are sm8650-only or proprietary. Useful pieces to *cherry-pick by URL* or rebuild from public source: `steamos-manager 26.4.1-2` (better: build from `holo/steamos-manager` git and add a `qcom,sm8750`/Odin device toml — DT detection landed in `6b6236c6`), `xdg-desktop-portal-holo`/`-gamescope`, `holo-zram-swap`, `fex-wtf`, `mangohud`, `scx-scheds 1.1.3.linux.steamos.2`, `deckard-steamvr-session`'s scripts as reference for gamescope args/`mesavars.sh`. Their `gamescope 3.16.29-1` binary links `libdrm 2.4.134` (newer than main's 2.4.131) → rebuild rather than reuse. Not usable: kernel/dtbs/firmware/u-boot/hw-support/steam-rel/mesa binary (private branch, a750-tuned, `conflicts mesa`).
- **Nothing on the deckard mirrors touches sm8750/a830.** The only forward signal for Odin 3 is steamos-manager's DT-keyed device table.
- **Recommendation:** keep the preview for the current release line; open a branch experiment "base bump to mash-20260305" (bootstrap + full package respin + base.list re-resolve + decky on python 3.14) as a one-variable change, separate from the mesa/gamescope pin bumps already queued. Watch `archlinux-deckard/archlinux/` for the next `mash-2026MMDD` (no `.pvt`) before committing.
